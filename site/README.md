# Сайт команды Loliland

Дерево заданий сборки для команды на модовом сервере Loliland. Описание всего сайта лежит в файлах проекта (`site_spec.md`).

## Что готово (первая рабочая версия)

- **Аккаунт.** Регистрация с ником с Loliland, вход, сброс пароля, личный кабинет, «Мои команды» по серверам.
- **Команда.** Создание с уникальным ID, вход по ID, закрытие и открытие входа капитаном, автозакрытие (по умолчанию через 24 часа без новых входов, капитан может поменять срок), ссылки-приглашения (на 1–5 входов или без ограничений, одноразовая по умолчанию), личные приглашения по нику, передача капитана, исключение, выход, роспуск команды.
- **Роли.** Капитан запускает раздачу, игроки перетаскивают роли на себя (или нажимают на роль), квестовик только один. Пока роли раздаются, все видят предварительный расклад заданий. Капитан нажимает «Распределение завершено», и план фиксируется.
- **Дерево заданий** («Общий прогресс»): время снизу вверх по эпохам, колонки по направлениям, связи между заданиями, у каждой карточки рамка цвета исполнителей, путь игрока по шагам со стрелками. Внутри эпохи задания стоят рядами, поэтому все стрелки смотрят вверх. Масштаб меняется кнопками «−» и «+» или колесом мыши с зажатым Ctrl, кнопка «Целиком» показывает всё дерево сразу.
- **Карточка задания**: описание, зачем, подпункты с отметками, что нужно до него и что оно открывает, состояние «не начато / в работе / готово».
- **«Мои задачи»**: свой путь по порядку: что в работе, что можно начинать, что ждёт других.
- **«Квесты»**: 27 квестов вкладки «Испытания» с четырьмя этапами, ведёт квестовик.

Пока нет: таблицы лидеров, конструктора закупок, биржи, мини-гайдов в карточках.

## Где выложен

Сайт: https://loliland-team.web.app (проект Firebase `loliland-team`, база Firestore в регионе `europe-west3`).

Обновить сайт после изменений в коде можно двумя способами:

- **через GitHub:** слить pull request в `main`, остальное сделает автовыкладка (см. ниже);
- **руками с компьютера, где настроен Firebase:** в папке `site` выполнить `git pull`, `npm install` (если менялись пакеты) и `npm run deploy`. Команда выкладывает и сайт, и правила базы.

## Автовыкладка через GitHub

Файл `.github/workflows/site.yml` делает три вещи:

- любой pull request, который трогает `site/`, проходит проверки: линтер, список заданий, правила базы, сборка;
- слияние в `main` после тех же проверок выкладывает правила базы и сайт;
- ту же выкладку можно запустить руками для любой ветки: на GitHub вкладка Actions → «Сайт» → Run workflow.

Чтобы выкладка заработала, один раз нужен ключ:

1. В консоли Firebase открыть Project settings → Service accounts и нажать Generate new private key. Скачается файл `.json`.
2. На GitHub открыть Settings → Secrets and variables → Actions → New repository secret. Имя `FIREBASE_SERVICE_ACCOUNT`, значение: всё содержимое файла.
3. Файл с ключом удалить с компьютера. Ключ даёт полный доступ к проекту Firebase, поэтому жить он должен только в секретах GitHub.

Настройки веб-приложения (`apiKey` и остальное) в репозитории не лежат. Для сборки они берутся с самого сайта, по служебному адресу Firebase Hosting `/__/firebase/init.json` (`scripts/ci-env.mjs`). Если так не получится, их можно задать переменными репозитория `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN` и `VITE_FIREBASE_APP_ID` (Settings → Secrets and variables → Actions → Variables).

Правила базы выкладывает `scripts/deploy-rules.mjs`. Индексы базы автовыкладка не трогает: сайту они пока не нужны.

## Из чего сделан

- **Firebase** (Google), бесплатный план Spark, без карты:
  - **Hosting** — сам сайт (адрес вида `имя-проекта.web.app`);
  - **Authentication** — регистрация и вход по почте и паролю;
  - **Firestore** — база, изменения видны всем сразу.
- **React + TypeScript + Vite** — сам сайт. Серверного кода нет: всю логику делает сайт в браузере, а что кому можно, проверяют правила базы.

## Как распределяются задания

Расчёт лежит в `src/lib/plan.ts` и одинаковый у всех, поэтому во время раздачи ролей каждый видит один и тот же предварительный расклад.

- Задание роли получает тот, у кого эта роль. Если роль взяли несколько человек, её задания делятся между ними поровну по нагрузке. Задание «все» получают все, «любой свободный» получает наименее загруженный.
- Нагрузка считается в условных часах по сложности: лёгкое 0,5 ч, среднее 2 ч, сложное 6 ч, суперсложное 12 ч. Сколько ролей взял, столько и работы: у человека с двумя ролями её примерно вдвое больше.
- Роль, которую никто не взял, не теряется: её задания уходят наименее загруженным, а капитан видит предупреждение.
- Квестовик идёт параллельно: квестовые задания числятся за ним отдельно. Если квестовика нет, квесты ведёт участник с наименьшим числом ролей.
- Путь игрока идёт по эпохам, а внутри эпохи по рядам дерева: снизу вверх, в ряду слева направо. Задание всегда стоит выше тех, от которых зависит. Два задания одного человека не стоят на одном шаге.
- После «Распределение завершено» план записывается в базу. Капитан может вернуться к ролям и завершить заново: задания пересчитаются, отметки останутся.

## Как устроено дерево

- **Ряды.** Ряд задания внутри эпохи считает `src/data/hitech/index.ts`: задание встаёт в самый нижний свободный ряд своей колонки, но строго выше заданий этой же эпохи, от которых зависит. Эпохи тоже идут снизу вверх, поэтому ни одна связь не смотрит вниз. Общий порядок заданий (`order`) идёт по эпохам, рядам и колонкам, и путь игрока строится по нему же: вниз он не возвращается, а в одном ряду идёт слева направо.
- **Масштаб.** Это свойство `zoom` на доске (`TreeBoard.tsx`). Шапка, полосы дней и подписи эпох получают обратный масштаб и остаются обычного размера. Ширину доска всегда занимает целиком, поэтому при отдалении колонки не сужаются, а ряды становятся ниже. Мельче 66% карточка сжимается в строку: номер и начало названия. «Целиком» подбирает масштаб, при котором всё дерево помещается в окно. Выбранный масштаб запоминается в браузере (`localStorage`, ключ `treeZoom`).
- **Линии.** Связи и путь игрока рисуются в слое SVG поверх сетки по измеренным положениям карточек. Браузеры по-разному считают размеры внутри `zoom`, поэтому дерево меряет линейку известной длины и переводит всё в пиксели самой доски.
- **Узкие колонки.** Когда название колонки не помещается (мелкий масштаб на телефоне), вместо него показывается значок из `GROUPS` в `src/data/hitech/extras.ts`.

## Данные в базе

| Где | Документ | Что лежит |
|---|---|---|
| `users` | uid | `nickname`, `nicknameLower`, `createdAt` |
| `nicknames` | ник в нижнем регистре | `uid` (чтобы ник не заняли дважды) |
| `teams` | ID команды (6 символов) | `name`, `server`, `captainUid`, `members`, `memberNicks`, `open`, `openedAt`, `autoCloseHours`, `phase` (`gathering` → `roles` → `running`), `roles`, `questRunner`, `invited`, `planVersion`, `createdAt` |
| `teams/{id}/state` | `plan` | кто какое задание делает: пишет капитан при «Распределение завершено» |
| `teams/{id}/state` | `progress` | состояния заданий, отмеченные подпункты, этапы квестов |
| `teams/{id}/invites` | токен ссылки | `maxUses` (0 значит без ограничений), `uses`, `revoked`, `by`, `at` |
| `teams/{id}/joins` | uid | отметка о входе по ссылке (связывает вход со ссылкой) |
| `invitations` | `{ID команды}_{uid}` | личное приглашение, которое игрок видит в кабинете |

## Как обновить список заданий

Согласованный список живёт в файлах проекта. Чтобы перенести его на сайт:

```bash
cd site
node scripts/import-tasks.mjs <tasks_list.txt> <tasks_draft.md>     # пишет src/data/hitech/tasks.ts
node scripts/import-quests.mjs <ispytaniya_quests.json>             # пишет src/data/hitech/quests.ts
npm run test:unit                                                   # проверить связи, эпохи и распределение
```

Колонки дерева, подпункты и оговорки пишутся руками в `src/data/hitech/extras.ts`: новому заданию там нужно указать колонку. Ряд внутри эпохи и место в общем порядке сайт считает сам. После изменений поменяй `VERSION` в `src/data/hitech/index.ts`: команды, которые уже распределили задания, увидят подсказку, что список обновился и капитану стоит завершить распределение заново.

## Запустить у себя без настоящего проекта

Нужен Node.js 22+ и Java 11+ (для эмулятора базы).

```bash
cd site
npm install
npm run emulators      # в одном окне: локальные «Firebase» на компьютере
npm run dev:local      # в другом окне: сайт на http://localhost:5173
```

## Проверки

```bash
npm run test:unit      # список заданий и распределение
npm run test:rules     # правила базы (сам поднимает эмулятор, остальные эмуляторы на это время останови)
npm run lint
npm run build
```

Весь сценарий в браузере (создание команды, вход по ID, ссылке и приглашению, роли, стрелки и масштаб дерева, задания, квесты, перераспределение, роспуск). Нужны запущенные `npm run emulators` и `npm run dev:local`, а ещё Playwright с Chromium в системе (`npm i -g playwright && npx playwright install chromium`):

```bash
node tests/e2e/scenario.mjs      # скриншоты кладёт в tests/e2e/shots
```

## Выложить в интернет (один раз)

1. Зайти на https://console.firebase.google.com под Google-аккаунтом и создать проект (Google Analytics можно выключить).
2. **Build → Authentication → Get started → Email/Password → включить.**
3. **Build → Firestore Database → Create database**, регион `eur3 (europe-west)`, режим production.
4. **Project settings → General → Your apps → значок `</>`** (веб-приложение), любое имя. Скопировать значения `apiKey`, `authDomain`, `projectId`, `appId`.
5. В папке `site` создать файл `.env.local` по образцу `.env.example` и вставить туда эти значения. Они не секретные: защищает базу `firestore.rules`.
6. Выложить:

```bash
cd site
npx firebase login
npx firebase use --add          # выбрать созданный проект
npm run deploy                  # собирает сайт и выкладывает сайт и правила базы
```

Сайт откроется по адресу `https://<id-проекта>.web.app`.

## Лимиты бесплатного плана

Хостинг: 10 ГБ места и около 360 МБ трафика в день. Firestore: 50 000 чтений и 20 000 записей в день, 1 ГБ данных. Для нескольких команд этого хватает с большим запасом. Платные функции (Cloud Functions, например для парсера Loliland) требуют тарифа Blaze с картой; парсер можно будет запускать и бесплатно через GitHub Actions.
